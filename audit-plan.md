## 1. Security & Reliability

### 1.1 🔴 Dashboard API has no authentication

**File:** `internal/dashboard/server.go`  
**Risk:** The service runs in Docker on a remote VM. The dashboard port is exposed externally. Without auth, anyone with network access can delete downloads from TorBox, unhide files, or manipulate the filesystem.

**Fix:** HTTP Basic Auth for all dashboard endpoints:

**Architecture:**
1. **New env vars:** `DASHBOARD_USERNAME` (default: `admin`) and `DASHBOARD_PASSWORD` (default: empty = no auth).
2. **When `DASHBOARD_PASSWORD` is set**, all dashboard endpoints (HTML, SSE, API) require Basic Auth. Browser automatically shows a native login dialog and caches credentials for the session. No custom login form or JS auth logic needed.
3. **When `DASHBOARD_PASSWORD` is empty** (default), dashboard is accessible without auth — for localhost or trusted-network deployments.
4. **`/metrics` and `/healthz` remain unauthenticated** regardless — they're on the same ServeMux but don't require auth (Prometheus needs unauthenticated access).
5. **For Docker deployment** — user adds `-e DASHBOARD_PASSWORD=some-secret` to `docker run` or `docker-compose.yml`. Browser prompts for login on first visit, then remembers for the session.
6. **Implementation:** Add a middleware function that checks `r.BasicAuth()` against `DASHBOARD_USERNAME` / `DASHBOARD_PASSWORD`. Apply it to all dashboard routes except `/metrics` and `/healthz`.

**Implementation:**
- `internal/dashboard/server.go`: Add `apiKey string` field to `Server`. In `handleIndex`, inject `window.__API_KEY__` into the HTML. In `handleDelete`/`handleUnlike`, validate `Authorization: Bearer <key>` header. If `apiKey == ""`, return 401.
- `internal/dashboard/dashboard.go`: Accept `apiKey` in `NewServer`/`NewHandler`.
- `internal/metrics/server.go`: Accept `apiKey` in `NewServer`.
- `cmd/torbox-media-center/main.go`: Read `DASHBOARD_API_KEY` env var, pass to dashboard/metrics server constructors.
- `internal/dashboard/static/app.js`: Read `window.__API_KEY__` and set `Authorization: Bearer` header on all fetch calls to `/api/delete` and `/api/unhide`.

### 1.2 🟡 Dashboard SSE endpoint has no connection limit

**File:** `internal/dashboard/server.go:110-145`  
**Risk:** Each SSE connection holds a goroutine + ticker. A malicious or buggy client can open many connections, exhausting goroutines.

**Fix:** Add a `sync/atomic` counter for active SSE connections; reject new ones if `> maxSSEConns` (e.g., 10). Close oldest connection if needed.

### 1.3 🟡 TorBox API key logged in PermalinkURL

**File:** `internal/fusefs/fs.go:618`  
**Current:** `PermalinkURL` embeds the API key directly in the CDN URL: `?token=<apiKey>&...`  
**Risk:** The token appears in logs (debug mode), metrics, and any error output. This is by design (TorBox CDN requires the token in the URL), but debug logs should redact it.

**Fix:** In debug log lines that print CDN URLs, truncate or redact the `token=` parameter. Add a `redactToken(url string) string` helper.

### 1.4 🟡 Dashboard delete endpoint: download_kind not validated

**File:** `internal/dashboard/server.go:195-221`  
**Current:** `handleDelete` accepts any string for `download_kind` — only the TorBox client validates it maps to a real API path. Invalid kinds return a confusing error from TorBox.

**Fix:** Validate `download_kind` against `["torrent", "usenet", "webdl"]` before proceeding. Return 400 with a clear message for invalid values.

### 1.5 🟡 apiGet cache eviction is O(n)

**File:** `internal/torbox/client.go:266-282`  
**Current:** When the API response cache exceeds 100 entries, eviction scans all entries to find the oldest. Under load with many concurrent requests, this linear scan holds the write lock.

**Fix:** This is low priority (100 entries, short lock), but for correctness, replace the `map[string]cacheEntry` with an ordered map or LRU. Not urgent.

### 1.6 🟢 TorBox API client: no request body size limit

**File:** `internal/torbox/client.go:231`  
**Current:** `io.ReadAll(resp.Body)` reads the entire response without a size limit. A malicious or buggy TorBox API could return an enormous response.

**Fix:** Use `io.LimitReader(resp.Body, maxResponseSize)` (e.g., 10 MB). The TorBox API responses should never exceed a few MB.

### 1.7 🟢 SQL LIKE pattern in UnhideDownload / IsDownloadFullyHidden

**File:** `internal/state/db.go:339,362`  
**Current:** Uses `content_key LIKE ?` with a prefix pattern (`torrent:123:%`). This works correctly because `%` and `_` are unlikely in content keys, but it's technically not injection-safe if content keys contained those characters.

**Fix:** This is fine for internal use (content keys are generated by our code, not user input). No change needed, but add a comment noting this assumption.

### 1.8 🟢 race condition on apiSem (minor)

**File:** `internal/torbox/client.go:205-206,319-320`  
**Current:** `apiSem` is an unbuffered channel used as a mutex (capacity 1). This serializes ALL API calls — both reads and writes. It's correct but limits throughput.

**Fix:** Consider making it buffered (e.g., capacity 3-5) to allow more concurrent API calls. The TorBox API already handles rate limiting. Not urgent — current design is safe.

## 3. Documentation Alignment

### 3.1 🟡 README: `FUSE_WRITABLE` description is misleading

**File:** `README.md` — Configuration table  
**Current:** `Enable write support: deleting files hides them locally and can remove downloads from TorBox via dashboard`  
**Issue:** "can remove downloads from TorBox via dashboard" is correct, but the wording implies the FUSE writable flag enables TorBox deletion. In reality, FUSE writable only enables **hiding** files locally. TorBox deletion is always available via the dashboard API regardless of the `FUSE_WRITABLE` flag.

**Fix:** Change to: `Enable write support: deleting files hides them locally (deletion from TorBox is always available via dashboard)`

### 3.2 🟡 README: Missing `DASHBOARD_API_KEY` documentation

**Issue:** Once we add authentication for dashboard mutating endpoints (item 1.1), the env var needs to be documented.

**Fix:** Add to the configuration table:
```
| `DASHBOARD_API_KEY` | *(none)* | API key for dashboard mutating endpoints (delete, unhide). If not set, no auth is required. |
```
